**Injection pattern — precedent vs novelty (plan doc §20).** The sub-graph-assembly *API* (new descriptors on one JobSpecification + `spec.connect` + partition constraints + roots) has solid precedent in standalone job builders — `FlushDatasetUtil`, `RebalanceUtil`, `FeedOperations`, `Secondary*OperationsHelper` — and creating connectors on `builder.getJobSpec()` from a physical op is what `AbstractExchangePOperator` does. BUT those own the *entire* JobSpec (standalone jobs); Route B assembles a sub-graph *inside an Algebricks-generated optimized plan, under one logical node*, from `contributeRuntimeOperator`, registering op1 as the node's door (op2–op5 internal). No existing asterix-algebra physical op injects >1 runtime op from contributeRuntimeOperator — **Route B is first-in-AsterixDB for that framing**. Mechanics copied from the precedents; the context was new/unproven → that's why M2 (job-gen injection) was the top risk and we validated end-to-end on a real 2-NC run rather than trusting a template. Call this out for any reviewer / upstreaming.

**Recap of the design.** The CLUSTER BY exact-init OVERSAMPLE_LOOP (`initMode="kmeansPP-exact-loop"`) as a **5-operator pipelined systolic sub-graph** so it works **multi-NC** (Route A's single-operator in-JVM-barrier is single-NC only).

**Shape (Route B):** one logical `OVERSAMPLE_LOOP` op whose physical op INJECTS a sub-graph onto `builder.getJobSpec()`:
`Op1 Cost/Controller(P) → Op2 PhiMerge(1 node) → Op3 Sample(P) → Op4 PoolMerge(1 node) → Op5 Release(P)`, looping via an **intra-NC shared permit** (Op5 releases → Op1 re-acquires) + a **growing pool run file** (Op5 appends, Op1/Op3 re-read) — cross-NC data on pipelined `MToNBroadcast` connectors (data plane), loop-back is joblet-state (no cyclic edge). Op1 is the registered descriptor: **port 0 = final pool (KIND_POOL envelopes, part 0) → WEIGH**, port 1 = per-round Σ → Op2. Single-node merges' "all P received?" = the barrier (needs **end-of-round markers** since Bernoulli draws are variable-count). Adaptive gate: physical op reads `getNumberOfNodes()`; nNC==1 → Route A barrier op, nNC>1 → this sub-graph (D1: replace-vs-adaptive still open).
