2. **Crash / failure-recovery for the 3-job vtree build — IMPORTANT** — `QueryTranslator.java:2147`, unresolved. A vtree index is built over 3 jobs (quantization training → static-structure → bulk load). A job that *throws* is compensated (drop-index job + drop metadata record). But on **node crash mid-build**, restart only drops the pending-op **metadata** record (`MetadataBootstrap` ~L596); the on-disk pieces (quantized `LocalResource`, Job-2 static-structure component, partial Job-3 bulk-load) fall to single-component LSM invalid-component recovery, which is built for the one-component secondary case and may not cover the multi-piece vtree layout. Exposure = orphaned artifacts / disk leak / stale files on same-name recreate (NOT wrong results — index stays `PENDING_ADD_OP`/invisible until one atomic flip). Follow-up: failure-injection matrix at each job boundary (crash after Job1 / after Job2 / mid-Job3) asserting metadata AND on-disk both come back clean; make the pending-index rollback tear down the whole vtree index directory rather than rely on per-component recovery.
